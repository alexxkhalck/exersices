Мета роботи
Закріпити на практиці фундаментальні принципи об'єктно-орієнтованого програмування (інкапсуляція,
успадкування), освоїти роботу з файловою системою (серіалізація/десеріалізація даних) та реалізувати
паттерн «Ітератор» для обходу колекцій.

Технічні вимоги та хід виконання
1. Проектування архітектури класів (Успадкування та Інкапсуляція)
Батьківський клас Laptop (Ноутбук):

Має містити захищені або приватні поля (інкапсуляція): бренд (brand), розмір екрану (screen size), ціна
(price), об'єм оперативної пам'яті (RAM).

Доступ до полів має бути реалізований виключно через публічні методи доступу (геттери).

Дочірній клас AppleLaptop (або інший конкретний бренд):

Має успадковувати базовий клас Laptop.

Повинен розширювати функціонал батьківського класу специфічними для цього бренду полями (наприклад, назва
моделі та тип процесора/чіпа).

Конструктор дочірнього класу обов'язково має викликати конструктор базового класу (super).

2. Бізнес-логіка та аналітика даних
Реалізувати алгоритм, який приймає масив (або список) об'єктів ноутбуків та знаходить серед них екземпляри
за наступними критеріями:

Ноутбук з найбільшим екраном.

Ноутбук з найменшим екраном.

Найдешевший ноутбук.

Найдорожчий ноутбук.

Ноутбук з найбільшим об'ємом оперативної пам'яті.

Ноутбук з найменшим об'ємом оперативної пам'яті.

3. Робота з файлами (I/O)
Знайдені в результаті аналітики об'єкти необхідно зберегти у файл (рекомендовано текстовий формат або
JSON для збереження структури).

Реалізувати функцію зчитування даних із цього файлу з подальшим відновленням (десеріалізацією) даних назад
в об'єкти класів.

4. Виведення даних за допомогою ітератора
Розробити власний клас-ітератор (або використати вбудований інтерфейс ітератора мови програмування) для
обходу структури з результатами.

Фінальний вивід зчитаних із файлу результатів у консоль має відбуватися виключно через ітератор у зручному
та читабельному вигляді.

Критерії оцінювання / Чек-лист для перевірки:
Чи закриті поля класів від прямого доступу ззовні (інкапсуляція)?

Чи правильно викликається конструктор батьківського класу в дочірньому?

Чи створюється файл на диску і чи коректно з нього відновлюються об'єкти?

Чи працює виведення результатів через цикл, який використовує механізм ітератора?
